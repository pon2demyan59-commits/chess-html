# Релизный кандидат — 7 октября 2026

## Проверено в этой ветке

- JavaScript: синтаксис; допустимость линий всех банков задач; полнота переводов и параметров.
- История онлайн-партии и повторения восстанавливаются из серверного журнала.
- Часы используют серверное время и performance.now(), не системные часы игрока.
- Сетевые запросы ограничены; повторная синхронизация после ошибки/возврата вкладки; до синхронизации ходы заблокированы.
- Серверная функция проверяет JWT, участника, очередность и допустимость хода через локальную chess.js; результат вычисляет сервер.
- Запись защищена версией и блокировкой строки; награда за результат выдаётся один раз.
- Реальный Chromium: четыре языка × шесть размеров (320×568, 390×844, 667×375, 844×390, 1366×768, 1920×1080). Доска, кнопки, превращение и длинный результат доступны.
- В имитации серверного API: поиск «везде», ход, потеря связи, восстановление и перезагрузка партии.
- Отключённый разбор и недостижимый генератор фэнтези-SVG удалены.

## Порядок подготовки сервера

Рабочая база и серверная функция в этом изменении НЕ обновлялись. Клиент этой ветки требует новый backend; старый API ходов не используется.

1. Сделать резервную копию и завершить активные партии старой версии. У старых матчей отсутствует полная история; её нельзя достоверно восстановить из FEN.
2. Запустить `python scripts/build_backend.py`; проверить `dist/backend-upgrade.sql` на отдельной базе Supabase. Файл объединяет схему, снимок прежних функций, очередь, присутствие и защищённую запись в одной транзакции. SQL-тест на отдельной базе в текущей среде не выполнен.
3. Применить проверенный SQL. Он закрывает прямые клиентские вызовы старых функций хода, таймаута и выхода. Не применять отдельный legacy-functions.sql после secure-match.sql.
4. Развернуть `supabase/functions/chess-match` с конфигурацией `supabase/config.toml`. `verify_jwt=false` нужен для текущих ключей; функция сама проверяет Bearer JWT через `auth.getUser`, включая анонимные сессии. Секрет service_role существует только в окружении сервера.
5. Проверить новую партию на двух устройствах: каждый контроль времени, добавление секунд, таймаут, недопустимый ход, чужой матч, повторная отправка, выход, разрыв связи, полная история.
6. Проверить, что вызов commit_validated_match обычным игроком запрещён. В Supabase разрешить необходимые внешние подключения и Anonymous Sign-ins.
7. После успешного серверного прогона публиковать клиент. Старые клиенты не смогут отправлять ходы после обновления сервера — обновление должно быть согласованным.
